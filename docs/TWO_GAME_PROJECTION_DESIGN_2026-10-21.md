# 小伢的江与万朝战域：点云场景设计与升级接口

日期：2026-10-21。继乱世执棋的城门与令印、首页统一舞台完成接入之后，细化另外两款游戏。以下场景为作品集主题展示，不冒充游戏实机、精确地理模型或已经完成的可玩地图。

## 小伢的江：江城与成长

**表达目标**：一眼看到「孩子面对家乡」，同时能从长江、长桥和五重飞檐联想到武汉。主体是一段成长记忆，构图从人到江再到城市。

| 层次 | 具体设计 | 显示作用 |
| --- | --- | --- |
| 前景 | 背着书包的孩子、河岸和零散石块 | 情感起点；人物由头、躯干、四肢、书包的实体表面组成 |
| 中景 | 弯曲江面、两岸线、顺流的细亮纹 | 引导目光，连接孩子和地标；不用矩形底座 |
| 主地标 | 五层递减的飞檐、开放廊柱、栏杆和登临台阶 | 稳定的纵向轮廓与识别中心；原海报作为视觉出处 |
| 后景 | 横向钢桁架长桥、桥墩 | 与高塔形成横竖对比，较低对比避免抢主体 |

色彩使用银白点云与冰蓝强调，深蓝黑背景。人、屋檐、岸线较亮，地基退后；静止状态就要能读懂人物与城市的距离。

**3.2 秒演示**：童年起点（孩子先亮）→ 沿江寻迹（冰蓝信号沿江的纵深方向推进）→ 江城回响（塔和桥接续亮起后恢复稳定）。点击播放一次，可暂停、继续；不无限闪烁。手动拖动会暂停演示，以免观察时丢失当前阶段。

**本轮资产**：38,000 点；确定性采样；真实三维位置、表面法向、亮度、分组、部件语义。移动端降采样为 18,000 点。几何入口为 `buildMemoryProjection()`，演绎模式 `storyMode: 1`。

**后续升级空间**：以真实角色模型替换人物表面采样；地标模型替换程序化塔；把现有三个段落扩展为童年、求学、离乡、返乡四段。保留 `positions / normals / tones / groups / parts / seeds` 数据接口和人物故事起点，展示 UI 无需重做。若只使用生成视频，可作为固定视角素材层，不能沿用实时旋转能力；本次采用实时点云以保留观察自由。

## 万朝战域：连续地形与路径选择

**表达目标**：从地形中读出策略矛盾——外围资源扩张与中央争夺。所有区域属于一片地形，路网使它们发生关系。

| 区域 | 具体设计 | 策略表达 |
| --- | --- | --- |
| 中央 | 八边形城墙、入口、层叠主楼与低矮附属建筑 | 中央争夺的焦点 |
| 山口 | 两段山脊、窄口、连续高程与补给队列 | 路线的收束与行军尺度 |
| 森林 | 分层树冠与树干组成的密集树林 | 地形边界与路线区分 |
| 湿地 | 弯曲水道、浅岸、低矮芦苇 | 与山口、林地区别鲜明的地貌 |
| 外围 | 矿石、农田与小型建筑 | 中央之外仍值得争取的资源 |
| 路网 | 入城支路、沿外围连接的道路 | 选择中央或外围的联系，不拆成三个悬浮平台 |

银白点云配灰绿强调。俯视角较另外两景更高，优先展现山口、城和路网的空间关系；地形面的亮度低于道路、屋檐和资源，避免一大片噪点掩盖策略内容。

**3.2 秒演示**：中央据点（中央城局部发光）→ 路径扩散（信号向外推进，道路与边界增强）→ 资源响应（外围结构被依次扫过后恢复稳定）。这是设计概念的演绎，不表示实装的战斗逻辑或寻路算法。

**本轮资产**：40,000 点；连续不规则地表与真实三维物件；入口 `buildTerrainProjection()`，模式 `storyMode: 2`，起点在中央城。移动端同样 18,000 点。项目状态继续读取真实内容数据「制作中」，保留「策划案完成、地图灰盒待制作」的原资料。

**后续升级空间**：用地图灰盒高度场替换地形函数；采样实际三阵营建筑；把路网升级为明确的路线曲线与可选择的分支；未来接入资源类型、运输方向和阵营信息时扩展点属性。仍复用现有舞台、相机、降级、键盘和项目链接。

## 共用工程与验收

- 一次只保留一个 WebGL 画布和一个场景的 GPU 资源；三个几何结果只做有限内存缓存。
- 异步选择按版本号提交，最后一次选择生效；场景替换释放旧缓冲、着色器与程序。
- 默认静止，切换才扫描，播放才演绎；离屏、后台、暂停和卸载停止请求动画帧。
- `prefers-reduced-motion` 禁用扫描过渡和演示播放，保留手动观察。无法运行 WebGL 时使用原海报或既有地图示意及项目链接。
- 页面标注「主题场景 · 展示设计」，提供原作图片切换；中文和英文信息保持同一真实项目数据。
- 本轮检查以本地浏览器、响应式尺寸、生命周期自动检查和生产构建为依据；未宣称所有 GPU、真机或参考官网逐像素一致。
